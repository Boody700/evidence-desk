# Validation record

## Corpus and model provenance

- Both public NIST PDFs were downloaded from their publication URLs and parsed with PDF.js.
- Source file SHA-256 hashes, physical page counts and publication metadata are recorded in `data/source-manifest.json`.
- The corpus has 112 physical PDF pages and 331 chunks; every chunk retains one document ID and one page number.
- Passage embeddings have 384 finite components, normalized before rounding for the prebuilt payload.
- Both quantized ONNX weight hashes match the LFS metadata at the pinned Hugging Face revisions.
- The native benchmark was reproduced with the pinned revisions after verifying their checksums.
- The patched dependency set reports zero vulnerabilities at the audit performed during this build.

## Automated checks

Nine Node test groups pass:

1. Page-bound chunking and normalized text.
2. BM25 relevance and document-scope restrictions, including empty scope.
3. One visible passage per physical source page.
4. Tokenizer-to-source alignment with punctuation spacing, absent answers and substring false matches.
5. Explicit semantic/extraction acceptance gates.
6. Token F1, normalization, partial matches and abstention.
7. Embedding dimension checks.
8. Real-corpus, benchmark-population and source-containment reconciliation.
9. Pinned runtime configuration and the static host asset-size budget.

The production worker bundle and app module pass JavaScript syntax/build checks. The browser runtime CDN is pinned to the exact installed dependency version; public module availability and CORS were checked. The runtime was moved off the static asset bundle because its Asyncify WASM file exceeds the hosting service's 25 MiB per-file limit. A regression check enforces the final static asset size budget.

## Browser verification

The actual browser WASM path extracted the confabulation definition from the starter corpus, cited Generative AI Profile PDF page 10, and highlighted the same words in its full-page text.

A clearly labeled fictional TXT fixture was uploaded through the file chooser. Research was scoped to that upload; the question “Who is the Atlas project owner?” returned “Mira Chen” with a section-1 citation. Removing the upload removed its related answer and passages.

A 48-page PDF was uploaded in Evidence search mode and yielded 133 searchable passages without downloading additional AI weights for indexing. This verifies the browser PDF parser independently of the offline corpus-preparation script.

Desktop and 390-pixel phone-width layouts were checked, including actual viewport/client widths and absence of page-wide horizontal overflow. Library source-selection controls, cancellation, and evidence-only behavior were exercised. The version-pinned runtime CDN path was then retested with a successful cited answer; no application console errors or warnings were observed in that final pass. Browser checks are smoke tests of selected flows, not a full accessibility or multi-device performance certification.

## Evaluation interpretation

The final fourteen-question diagnostic report is generated by native CPU inference. Browser WASM inference is smoke-tested on selected examples, not evaluated on all forty-two questions. Floating-point and device differences can affect scores near thresholds.

Retrieval strategy and abstention gates use fourteen original development questions. The original fourteen-question test became diagnostic after design problems were observed. A fresh final test was then used, and rerun after a deterministic span-alignment fix without changing retrieval/gates based on its outcomes. The history is preserved in `reports/initial-diagnostic.json` and the case study.

Final retrieval top-three page hit rate is 100% over ten answerable questions; token F1 is 58.9% including declined answerable questions. Four unsupported examples were declined, while four answerable questions were also declined. All accepted spans occur in their cited passage; that is not a semantic-correctness guarantee. No broader production accuracy is claimed.

## Reproduction commands

```text
npm ci --ignore-scripts
npm run prepare-data
npm run evaluate
npm run build
npm test
npm start
```

Node 22.3+ and network access are required for a full rebuild. The included prebuilt app can be served with `npm start` without rebuilding dependencies.
